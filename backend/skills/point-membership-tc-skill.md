# 포인트/멤버십형 서비스 유형 TC 설계 스킬

고객 대상 화면이지만 실제 상품 판매·결제(PG 연동)는 이 프로젝트가 직접 처리하지 않고,
포인트 적립/차감, 쿠폰, 응모/당첨, 혜택 지급이 핵심인 서비스에서 기획서만으로는
놓치기 쉬운 예외 케이스 체크리스트. TC 생성 시 이 문서의 항목들을 기획서 내용과 함께
검토하여, 기획서에 명시되지 않았더라도 반드시 하나 이상의 TC로 다뤄야 한다.

주의: 이 유형은 자체 장바구니/결제(PG)/배송을 소유하지 않는다. 결제·구매는 외부
(입점몰 등)에서 이미 끝난 상태로 들어오는 결과값일 뿐이므로, 아래 항목들은 그 결과값을
"어떻게 반영/집계/보상하는가"에 집중한다. PG사 콜백 처리, 재고 관리, 배송 상태 처리 같은
직접 커머스 항목은 이 프로젝트 범위가 아니면 다루지 않는다.

## 1. 포인트 적립 / 차감
- 적립 대상 금액 산정 기준(예: 결제금액의 N%)과 실제 반영 시점 사이의 지연/불일치
- 부분 취소·환불로 결제금액이 사후에 줄거나 0원이 된 경우, 이미 적립된 포인트의 회수 로직
- 적립률 계산 시 반올림/절사 기준이 명시돼 있는지, 안 돼있다면 그 기준에 따른 결과 차이
- 동일 구매건에 대한 중복 적립 시도(같은 결제건이 두 번 통지되는 경우 등)
- 포인트 차감(사용) 시 잔액 부족 상황 처리
- 여러 채널(복수 입점몰)에서 동시에 발생한 적립이 합산되는 방식

## 2. 포인트 유효기간 / 소멸
- 포인트 소멸 시효 도래 시점 경계값(만료 직전/직후에 사용 시도)
- 일부 소멸 처리 후 남은 포인트를 사용할 때 우선순위(먼저 적립된 것부터 소진되는지)
- 소멸 예정 포인트 안내가 실제 소멸 시점과 어긋나지 않는지

## 3. 쿠폰
- 동일 쿠폰 중복 적용 시도
- 중복 적용 불가 쿠폰 간 조합 시도
- 최소 주문 금액 미달 상태에서 쿠폰 적용 시도
- 쿠폰 유효기간 만료 직전/직후 경계값
- 최대 적용 가능 쿠폰 수 초과

## 4. 이벤트 응모 / 당첨 (복권, 추첨 등)
- 참여 횟수 제한 초과 시도(예: 1일 1회, 월 최대 N회 같은 경계값)
- 기간 마지막 날 여러 건이 몰릴 때 카운트가 정확히 초기화/누적되는지
- 결제금액이 0원이거나 사후에 취소된 구매건에 대한 참여 자격 처리
- 당첨자 발표 이후 정정(취소/재추첨)이 필요한 경우의 처리 절차
- 동일 사용자의 중복 참여 방지(부정 참여 포함)

## 5. 외부(입점몰 등) 연동 데이터 정합성
- 입점몰/결제수단별로 실적 반영 기준이 서로 다를 때 그 기준이 실제로 지켜지는지
- 외부 결제 데이터 수신이 지연될 때 적립 시점이 밀리는 것을 사용자가 알 수 있는지
- 외부에서 결제 정정/취소 통지가 뒤늦게 온 경우, 이미 지급된 혜택(포인트/당첨 등)의 사후 처리
- 방문판매 등 결제수단별로 실적 반영 기준이 다를 경우의 경계 케이스

## 6. 권한 / 인증
- 비로그인 사용자의 포인트 조회/사용/응모 시도
- 타인 계정의 포인트·쿠폰·응모 이력 조회 시도
- 세션 만료 중 응모/사용이 진행된 경우의 처리

## 7. 데이터 정합성
- 새로고침/재진입 시 응모 상태·포인트 사용 상태가 재검증되는지
- 동시 요청으로 인한 포인트 차감/응모 경합(동시성)
